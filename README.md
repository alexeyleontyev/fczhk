# ФКЖК — MVP 5

Telegram-бот и Mini App для организации пятничного футбола. Реализованы все пять MVP: запись, оплаты и ручные составы; оценки и автоматическая балансировка; результаты и личная статистика; аукцион капитанов; конкурс прогнозов с общим зачётом. Все повседневные действия доступны с телефона.

Приложение также работает как сайт в обычном браузере: отдельная кнопка «Войти через Telegram» использует тот же профиль и проверку участия в сообществе. Внутри Telegram Mini App вход выполняется автоматически.

Текущие команды, кнопки и публикации бота описаны в [документации Telegram-бота](docs/BOT.md).

История 17 игр из Google Sheets импортирована в локальную demo.db; порядок и исключения описаны в [документе импорта](docs/HISTORICAL_RESULTS_IMPORT.md). [Игровой рейтинг на OpenSkill](docs/PLAYER_RATING_OPTIONS.md) доступен для просмотра в разделе «Игроки» и как отдельный экспериментальный способ подбора составов. По умолчанию используются прежние оценки сообщества: проверка на 17 играх пока не показала преимущества OpenSkill перед простым прогнозом 50/50.

В разделе «Игроки» всем авторизованным участникам доступны общие зачёты по очкам (3/1/0), винрейту (победа — 2, ничья — 1, поражение — 0 из 2 за игру), голам, передачам и голам + передачам. Рядом показаны рейтинг OpenSkill и зачёт оценок сообщества с фильтрами «Атака + защита», «Атака», «Защита» и «Защита вратаря». Статистика матчей пересчитывается из актуальных завершённых результатов; автоголы не записываются бомбардирам. В зачёте сообщества участвуют только игроки, получившие оценки по выбранному амплуа.

Общие зачёты и OpenSkill можно фильтровать по имени и числу игр: по умолчанию показаны игроки с более чем 5 играми, а порог 0 показывает всех. В рейтинге сообщества доступен поиск по имени. В карточке игрока сразу видны пять последних игр и три самых частых партнёра; остальные записи раскрываются отдельно.

Python управляется через **uv**; точные зависимости зафиксированы в `uv.lock`. Frontend: React + TypeScript + Vite, зависимости в `frontend/package-lock.json`. Рабочая БД — PostgreSQL; SQLite используется только в локальном демо и быстрых тестах.

## Локальное демо без Telegram

Требуются Python 3.12 (uv может установить его), uv и Node.js 22.

```sh
uv sync
npm --prefix frontend ci
npm --prefix frontend run build
uv run fczhk demo
```

Открыть **http://127.0.0.1:8000**. На экране входа выбрать администратора или игрока. Добавленные данные сохраняются в `.local/demo.db`; повторный запуск не сбрасывает их. Сервер демо слушает только loopback. Публикации имитируются локальным worker и явно помечаются «Демо»; в Telegram ничего не отправляется.

Демо содержит вымышленные имена, манеж, стоимость и реквизиты. Оно не использует реальный токен из `.env` и не предназначено для публичного размещения.

Демо не придумывает оценки от имени игроков: [589 исходных оценок сообщества](docs/COMMUNITY_RATINGS_IMPORT.md) импортированы с указанием авторов, а новые карточки появляются без рейтинга. В разделе «Игроки» можно оценить конкретного зарегистрированного участника или пройти список кнопкой «Оценить игроков». Администратор задает гостям и участникам без оценок временные значения в блоке «Рейтинги на эту игру». После финализации доступен блок «Подобрать команды». Ссылкой `http://127.0.0.1:8000/?game=<ID>` можно открыть конкретную игру.

При первом запуске этой ветки существующая демо-БД дополняется новыми таблицами; прежние данные не удаляются. Это специальный режим демо. Для рабочей PostgreSQL обязательна миграция, описанная ниже.

Для разработки интерфейса запустить дополнительно:

```sh
npm --prefix frontend run dev
```

Vite откроет адрес http://127.0.0.1:5173 и направит `/api` на backend :8000. При изменении backend перезапустить `uv run fczhk demo`.

## Реальное подключение Telegram

Порядок первого запуска, переноса истории и проверки в Telegram записан в [плане развёртывания](docs/DEPLOYMENT_PLAN.md).

1. Создать бота в BotFather. Получить токен и добавить бота администратором в разрешенный чат/канал: это нужно для надежной проверки членства. В месте публикаций выдать права публикации/редактирования сообщений бота.
2. Создать локальный `.env` по `.env.example`. Указать токен, числовые Telegram ID администраторов, чат сообщества, чат публикаций, username бота, публичный HTTPS-адрес и PostgreSQL URL. `.env` игнорируется Git.
3. В BotFather настроить Main Mini App на тот же HTTPS-адрес: кнопки постов используют прямые ссылки `https://t.me/<bot>?startapp=game_<id>`.
4. Применить миграции, запустить API и worker.
5. Выполнить `uv run fczhk configure-bot`. Эта явная команда изменяет меню, список команд и режим доставки обновлений вашего бота. Если задан `FCZHK_WEBHOOK_SECRET`, настраивается webhook; иначе webhook удаляется без потери ожидающих обновлений и нужен отдельный `uv run fczhk bot`.
6. В Mini App войти администратором, настроить место, время, стоимость, реквизиты и включить еженедельный шаблон. По умолчанию расписание выключено и реальные реквизиты не заполнены.

Подключение к настоящему Telegram и отправка реального поста не выполнялись при разработке: токен, чат и домен не предоставлены. Проверка Mini App внутри Telegram на реальных iOS/Android и один пробный сбор являются приемкой развертывания.

### Вход на сайт через Telegram

1. В Mini App **BotFather** выбрать того же бота, открыть **Login Widget** и добавить публичный адрес сайта (например, `https://football.example.com`) в **Allowed URLs**. Оставить алгоритм подписи **RS256**. См. [актуальную документацию Telegram Login](https://core.telegram.org/bots/telegram-login).
2. Скопировать **Client ID** в `.env`: `FCZHK_TELEGRAM_LOGIN_CLIENT_ID=<число>`. Для используемого потока JavaScript **Client Secret не нужен**. Значение `0` отключает браузерный вход; работа Mini App от этого не зависит.
3. Убедиться, что `FCZHK_PUBLIC_URL` совпадает с адресом сайта в браузере, включая протокол и нестандартный порт. Для проверки подписки бот должен быть администратором канала или чата, указанного в `FCZHK_COMMUNITY_CHAT_ID`.
4. Перезапустить приложение с обновлённым окружением; для Docker Compose пересоздать контейнер `app`. Открыть сайт в обычном браузере и нажать «Войти через Telegram». Если окно заблокировано, разрешить всплывающие окна для сайта и повторить вход.

Сервер проверяет подпись ID token по публичным ключам Telegram, издателя, Client ID, срок действия и привязку к попытке входа в этом браузере. Затем проверяет участие в сообществе и выдаёт обычную сессию приложения. Используется числовой Telegram ID, а не OIDC `sub` или username: повторный вход с того же аккаунта сохраняет карточку и права администратора. Запрашивается только публичный профиль; телефон и разрешение на личные сообщения не запрашиваются.

Сессия сохраняется в пределах вкладки, включая перезагрузку страницы. Ссылки `/?game=<ID>` продолжают работать после входа. При API-запросах участие в сообществе повторно проверяется с интервалом `FCZHK_MEMBERSHIP_CACHE_SECONDS` (по умолчанию 5 минут). Исторический профиль по одному совпадению имени автоматически не привязывается: игрок отправляет заявку из профиля, администратор подтверждает её в настройках. Выход из аккаунта отзывает текущую серверную сессию; просроченные сессии регулярно удаляет worker. Действующая сессия проверяется до повторного входа по initData.

Сайт должен иметь доступ к `telegram.org` для загрузки библиотеки входа, а сервер — к `oauth.telegram.org` для получения ключей. Не задавать `Cross-Origin-Opener-Policy: same-origin`: он блокирует взаимодействие с окном Telegram; допустим `same-origin-allow-popups`. Браузерные тесты используют имитацию Telegram; реальный вход проверяется после настройки BotFather и HTTPS.

### Запуск сервисов без Docker

```sh
uv run fczhk migrate
uv run fczhk serve
# В другом процессе:
uv run fczhk worker
# Только если выбран polling:
uv run fczhk bot
```

### PostgreSQL для локальных интеграционных проверок

```sh
docker compose up -d db
```

Для чистого окружения без `.env`: пользователь/БД `fczhk`, локальный пароль `local-development-only`, адрес `127.0.0.1:55432`. Этот пароль только для локальной разработки. Если `.env` задает `POSTGRES_PASSWORD`, используйте его. Docker volume сохраняется при остановке контейнера.

### Развертывание Docker + HTTPS

В `.env` обязательны настоящий пароль `POSTGRES_PASSWORD`, домен `DOMAIN`, а также `FCZHK_DATABASE_URL=postgresql+psycopg://fczhk:<URL-encoded-password>@db:5432/fczhk`. Для контейнеров база находится на `db:5432`, а не на localhost. Остальные значения Telegram задаются как выше.

```sh
bash scripts/deploy.sh ghcr.io/OWNER/REPOSITORY:FULL_40_CHARACTER_GIT_SHA
bash scripts/compose.sh exec app fczhk configure-bot
# Только для polling, когда WEBHOOK_SECRET пуст:
bash scripts/compose.sh --profile polling up -d bot
```

DNS домена должен указывать на сервер, порты 80/443 — быть доступны Caddy. Не запускать polling и webhook одновременно. API проверяет настройки и отказывается запускаться в production без Telegram, администраторов, HTTPS и PostgreSQL.

Миграции выполняет отдельный сервис `migrate`; API запускается после его успешного завершения, worker — после готовности API. Процессы получают SIGTERM напрямую. `/api/health` проверяет БД, `/api/health/ready` — worker и доставку, `/api/metrics` предоставляет защищённые метрики Prometheus. CI публикует проверенный образ с полным Git SHA; скрипт выпуска сохраняет backup до миграций. Порядок импорта, мониторинга и отката — в [инструкции эксплуатации](docs/DEPLOYMENT_PLAN.md). Не менять первоначальный пароль работающего volume через `.env` без отдельного изменения учетной записи PostgreSQL.

## Исправления надёжности и управление играми

- Блокирующие транзакции авторизации и webhook выполняются в потоках; соединение БД не удерживается во время проверки Telegram.
- Архив получает краткие карточки страницами: GET /api/matches?limit=20&offset=0, максимум 100. Полная карточка доступна по /api/matches/{id}, ближайшая — /api/matches/current. Изменение заявки обновляет текущую игру без повторной загрузки архива.
- Исторический рейтинг читает участников и голы пакетно; повторные расчёты кешируются по содержимому истории и автоматически меняются после исправления результата или слияния карточек.
- Будущую игру можно отменить с причиной, сохранив оплаты и историю. Ещё не созданную пятницу можно пропустить в настройках.
- Настройки показывают заявки на связь исторических профилей, очередь и ошибки публикаций. Для неопределённой доставки перед повтором нужно проверить чат.
- Backend разделён на маршруты по областям, frontend — на экраны и общий hook загрузки данных.

## Проверки

```sh
uv run ruff check src tests migrations scripts
uv run pytest -q
npm --prefix frontend run build
```

Дополнительные тесты PostgreSQL пропускаются без явного URL. Они применяют настоящие миграции и проверяют одновременное расписание, повторную запись, конфликт финализации, одновременное изменение одной оценки и обновление базы MVP 1 с сохранением данных. Для каждого теста создается отдельная случайная схема; только она удаляется после проверки. Дополнительно проверяются миграции MVP 3–5, конкурентные результаты и ставки, ревизии прогнозов и истечение дедлайна в ожидании блокировки.

```sh
FCZHK_TEST_DATABASE_URL=postgresql+psycopg://fczhk:local-development-only@127.0.0.1:55432/fczhk uv run pytest tests/test_postgres.py -q
```

Браузерные проверки самостоятельно запускают отдельный сервер на :8001 с временной БД. Сначала соберите frontend; работающий демо-сервер на :8000 не требуется:

```sh
cd frontend
npx playwright install chromium
npm run test:e2e
```

Браузерные сценарии создают игры, гостей, оценки, результаты, аукционы и прогнозы только во временной БД. Сценарий прогнозов ждёт наступления реального времени начала тестовой игры. Сервер и БД завершаются после проверки; `.local/demo.db` сохраняется без изменений. Скриншоты и трассировки находятся в `frontend/test-results/` и не коммитятся.

Проверка времени подбора на пяти воспроизводимых синтетических наборах, без БД:

```sh
uv run python scripts/benchmark_balance.py
```

Если среда ограничивает домашний кэш uv, локальные команды можно запускать как `uv --cache-dir .cache/uv run --no-sync ...` после `uv sync`.

## Доставка постов

Открытие сбора сохраняет игру и задание публикации одной транзакцией. Worker отправляет пост отдельно. После утверждения команд администратор нажимает «Опубликовать составы». Ошибка Telegram не отменяет утвержденные данные.

При определенном отказе Telegram отображается ошибка и доступен повтор. При сетевой неопределенности или перезапуске посреди отправки автоматический повтор запрещен: администратор проверяет чат и явно запускает повтор, чтобы не создавать незаметные дубли. Для больших сообщений сохраняются ID уже доставленных частей.

Изменение участников сбрасывает распределение и утверждение, старые посты помечаются неактуальными. Если Telegram не дает отредактировать старое сообщение, интерфейс сообщает об этом; администратор уведомляет чат и публикует новую версию.

## Резервное копирование

```sh
bash scripts/backup.sh /absolute/path/to/independent-backups
bash scripts/verify-backup.sh /absolute/path/to/independent-backups/ACTUAL_BACKUP.dump
```

Создаются новый архив pg_dump и SHA-256; проверка полностью восстанавливает архив в отдельный временный PostgreSQL без сети. [backup-offsite.sh](scripts/backup-offsite.sh) объединяет dump, restore и копирование через SSH. [Systemd timer](deploy/fczhk-backup.timer) запускает его ежедневно. Настройка внешнего хранилища, уведомлений и восстановление описаны в [плане эксплуатации](docs/DEPLOYMENT_PLAN.md). Старые копии автоматически не удаляются.

## Обновление MVP 1 → MVP 2

1. Сделать резервную копию PostgreSQL и проверить восстановление в отдельной БД.
2. Остановить старые API/worker/bot на время обновления; не запускать две версии приложения поверх одной БД.
3. Обновить зависимости: `uv sync --locked`, `npm --prefix frontend ci`, `npm --prefix frontend run build`.
4. С настроенным `.env` выполнить `uv run fczhk migrate`. Миграция `c2a486fe91d0` добавляет семь таблиц и служебную строку, не меняя игроков, заявки, оплаты и старые снимки составов. Повторное применение безопасно.
5. Запустить API/worker/bot. При использовании Docker выпустить проверенный образ через CI и запустить scripts/deploy.sh; миграции выполняются отдельной задачей до API.

Для уже утвержденных в MVP 1 команд не подставляются сегодняшние рейтинги задним числом: показывается отсутствие снимка. Новые утверждения сохраняют рейтинги и параметры подбора. Для отката предпочтительно восстановление предварительной копии: `alembic downgrade` удаляет новые таблицы с оценками и расчетами.

## Границы MVP 2

Результаты/голы и статистика относятся к MVP 3, аукцион — к MVP 4. Онлайн-оплаты не подключены: подтверждение перевода остается ручным.

Допуски балансировки и округление порога разнообразия при недоборе имеют предварительные значения, доступные администратору в настройках расчета. Для выпуска на реальных игроках их нужно подобрать совместно с организатором. Полный перебор гарантирует минимальный дисбаланс, но эвристика выбора разных вариантов не гарантирует глобальный максимум разнообразия. Если подходящих вариантов найдено меньше трех, приложение показывает причину и оставляет ручной режим.

## MVP 3: результаты

После начала утвержденной игры администратору доступен блок «Результат матча»: фактические участники, голы, передачи, автоголы и неизвестные авторы. Сохраните черновик либо завершите матч. Исправления обновляют статистику; профили и архив содержат ссылки на результаты. Подробности: [решения MVP 3](docs/MVP3_IMPLEMENTATION.md).

## MVP 4: аукцион

После финализации администратор назначает капитанов в блоке «Аукцион капитанов». Капитаны открывают одну игру в своих аккаунтах и подают закрытые ставки. Пауза, отмена и ручное завершение доступны администратору; история лотов и бюджеты видны игрокам. Подробности: [решения MVP 4](docs/MVP4_IMPLEMENTATION.md).

## MVP 5: конкурс прогнозов

После утверждения команд любой зарегистрированный игрок может прогнозировать счёт, даже если не участвует в матче. Создать и изменить прогноз можно строго до начала игры. Угаданные победитель и разница мячей дают 3 очка; только победитель или ничья — 1 очко. Вкладка «Прогнозы» показывает общий зачёт по всем завершённым матчам; исправления результатов пересчитывают очки. Подробности: [решения MVP 5](docs/MVP5_IMPLEMENTATION.md).

## Обновление до MVP 5

Сохраните резервную копию и проверьте восстановление. Остановите прежние API/worker/bot, установите зависимости и соберите frontend, выполните `uv run fczhk migrate`, затем запустите сервисы. После MVP 2 последовательно применятся `d3e718ba029c` (результаты), `e4f928cb13ad` (аукцион), `f5a039dc24be` (прогнозы) и `4e8493c19b02` (импортированные оценки). Старые игроки, заявки, оплаты, оценки и снимки сохраняются; старые игры не становятся завершёнными автоматически. Для локального демо достаточно перезапуска `uv run fczhk demo`.

Ветки MVP 2–5 последовательно сливаются в `main` через отдельные merge-коммиты после проверок. Результаты развертывания в настоящем Telegram не подменяются локальными проверками.
