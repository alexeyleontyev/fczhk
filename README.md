# ФКЖК — футбол по пятницам

Telegram-бот, Mini App и сайт для футбольного сообщества: запись на игры, ручное подтверждение оплат, подбор составов, результаты, рейтинги и конкурс прогнозов. Интерфейс рассчитан на телефон. В Telegram вход автоматический; в обычном браузере доступна кнопка «Войти через Telegram» с тем же профилем и проверкой членства.

В `main` объединены все пять MVP, импорт истории и оценок, браузерная авторизация и улучшения надёжности. [Оглавление документации](docs/README.md) · [Правила продукта](docs/TECHNICAL_SPECIFICATION.md) · [Выпуск и эксплуатация](docs/DEPLOYMENT_PLAN.md).

## Возможности

| Область | Что доступно |
| --- | --- |
| Организация игры | Шаблон пятницы, автоматическое или ручное открытие, отдельные очереди полевых и вратарей, резерв, гости, отметки оплаты |
| Управление | Финализация, административные замены, отмена будущей игры с причиной и сохранением оплат, пропуск ещё не созданной пятницы |
| Права | Владелец назначает и снимает администраторов в приложении; изменения сохраняются в БД и действуют без перезапуска |
| Составы | Ручное распределение, до трёх вариантов по оценкам сообщества, закрытый аукцион капитанов, отдельный экспериментальный OpenSkill |
| Результаты | Фактические участники, счёт по голам, передачи, автоголы и неизвестные авторы; исправления пересчитывают статистику |
| Игроки | Профили, история и партнёры, очки 3/1/0, винрейт, голы/передачи, средние оценки и OpenSkill, поиск и фильтр числа игр |
| Прогнозы | Прогноз счёта после утверждения и до старта; общий зачёт с начислением 3/1/0 |

| Доставка | Посты открытия, составов и отмены, пометка устаревших постов, видимая очередь и явный повтор проблемной доставки |
| Эксплуатация | Миграции, CI, проверенный Docker-образ по Git SHA/digest, readiness и метрики, backup с полным restore, offsite и ограниченный безопасный откат |

## Локальное демо без Telegram

Требуются Python 3.12, uv и Node.js 22:

```sh
uv sync --locked
npm --prefix frontend ci
npm --prefix frontend run build
uv run fczhk demo
```

Открыть **http://127.0.0.1:8000** и выбрать администратора или игрока. Демо слушает loopback, использует вымышленные данные и имитирует публикации; реальные токены из `.env` не используются. Данные сохраняются в `.local/demo.db`, повторный запуск не сбрасывает их. Демо не предназначено для публичного размещения.

Свежая установка создаёт демонстрационные данные без выдуманных оценок от имени игроков. В обновлённой локальной базе на 17.10.2026 есть 19 исторических игр и 563 исходных голоса (первый импорт 26.09 содержал 17 игр и 589 голосов): XLSX и `.local/demo.db` не включены в Git и автоматически не появляются после клонирования. Для повторения импорта нужны исходные выгрузки и [инструкции](docs/HISTORICAL_RESULTS_IMPORT.md). Временные рейтинги для участников без оценок задаёт администратор на конкретную игру.

Прямая ссылка на игру: `http://127.0.0.1:8000/?game=<ID>`. Для разработки интерфейса дополнительно запустить:

```sh
npm --prefix frontend run dev
```

Vite слушает `http://127.0.0.1:5173` и проксирует `/api` на backend :8000. При изменении Python перезапустить демо. Демо умеет создавать отсутствующие таблицы, но не заменяет Alembic при изменении существующей схемы; для production миграции обязательны.

## Стек и структура

Python 3.12, FastAPI, SQLAlchemy/Alembic, aiogram и PostgreSQL 17; React, TypeScript и Vite. Зависимости зафиксированы в `uv.lock` и `frontend/package-lock.json`. SQLite используется для демо и быстрых тестов.

```text
src/fczhk/      API по областям, бизнес-правила, авторизация, бот, worker, CLI
frontend/      Экраны Mini App/сайта, загрузка данных, Playwright
migrations/    Последовательные миграции PostgreSQL
tests/         Правила, API, безопасность, конкуренция и выпуск
scripts/       Импорт, измерения, deploy, backup, restore, rollback и smoke
deploy/        Caddy, systemd backup и примеры Prometheus
data/          Подтверждённые карты имён и поправки исходных выгрузок
docs/          ТЗ, справочники и решения этапов MVP
```

[Архитектура и узкие места](docs/ARCHITECTURE.md) · [API](docs/API.md) · [Настройки и CLI](docs/CONFIGURATION.md).

## Реальное подключение Telegram

Порядок первого запуска, переноса истории и проверки в Telegram записан в [плане развёртывания](docs/DEPLOYMENT_PLAN.md).

1. Создать бота в BotFather. Получить токен и добавить бота администратором в разрешенный чат/канал: это нужно для надежной проверки членства. В месте публикаций выдать права публикации/редактирования сообщений бота.
2. Создать локальный `.env` по `.env.example`. Указать токен, личный числовой Telegram ID владельца в `FCZHK_OWNER_ID`, чат сообщества, чат публикаций, username бота, публичный HTTPS-адрес и PostgreSQL URL. `.env` игнорируется Git.
3. В BotFather настроить Main Mini App на тот же HTTPS-адрес: кнопки постов используют прямые ссылки `https://t.me/<bot>?startapp=game_<id>`.
4. Применить миграции, запустить API и worker.
5. Выполнить `uv run fczhk configure-bot`. Эта явная команда изменяет меню, список команд и режим доставки обновлений вашего бота. Если задан `FCZHK_WEBHOOK_SECRET`, настраивается webhook; иначе webhook удаляется без потери ожидающих обновлений и нужен отдельный `uv run fczhk bot`.
6. В Mini App войти владельцем, настроить место, время, стоимость, реквизиты и включить еженедельный шаблон. Других администраторов назначить в разделе «Управление → Администраторы». По умолчанию расписание выключено и реальные реквизиты не заполнены.

Проверка Mini App внутри Telegram на реальных iOS/Android и один пробный сбор являются приёмкой развёртывания. Успешные локальные тесты с имитацией Telegram не заменяют эти проверки.

### Владелец и администраторы

`FCZHK_OWNER_ID` содержит числовой Telegram ID владельца. Он получает все административные возможности и доступ к панели «Управление → Администраторы». Владелец выбирает уже вошедшего через Telegram игрока и назначает либо снимает его права. Гостевую историческую карточку назначить администратором нельзя. Остальные администраторы управляют играми, но не ролями.

Назначения и отзывы сохраняются в БД, журналируются и применяются со следующего запроса, в том числе для уже выданной сессии. После изменения прав обновить страницу, чтобы обновился интерфейс. Владелец не может снять свои права через приложение; смена владельца выполняется оператором через `FCZHK_OWNER_ID` с новым запуском процессов. Владелец и администраторы также должны состоять в сообществе.

Для старых установок сохранён `FCZHK_ADMIN_IDS`: если `FCZHK_OWNER_ID` не задан или равен `0`, владельцем становится **первый** ID списка. Остальные ID дают начальные административные права, пока владелец не изменил их в приложении. Отзыв в БД имеет приоритет над списком и сохраняется после перезапуска. Для новой установки задать владельца явно, а legacy-список оставить пустым.

### Вход на сайт через Telegram

1. В Mini App **BotFather** выбрать того же бота, открыть **Login Widget**, при необходимости нажать **Switch to OpenID Connect Login** и добавить публичный адрес сайта (например, `https://football.example.com`) в **Trusted Origins**. Поле **Redirect URLs** для этого JavaScript-потока не требуется. Оставить алгоритм подписи **RS256**. См. [актуальную документацию Telegram Login](https://core.telegram.org/bots/telegram-login).
2. Скопировать **Client ID** в `.env`: `FCZHK_TELEGRAM_LOGIN_CLIENT_ID=<число>`. Для используемого потока JavaScript **Client Secret не нужен**. Значение `0` отключает браузерный вход; работа Mini App от этого не зависит.
3. Убедиться, что `FCZHK_PUBLIC_URL` совпадает с адресом сайта в браузере, включая протокол и нестандартный порт. Для проверки подписки бот должен быть администратором канала или чата, указанного в `FCZHK_COMMUNITY_CHAT_ID`.
4. Перезапустить приложение с обновлённым окружением; для Docker Compose пересоздать контейнер `app`. Открыть сайт в обычном браузере и нажать «Войти через Telegram». Если окно заблокировано, разрешить всплывающие окна для сайта и повторить вход.

Сервер проверяет подпись ID token по публичным ключам Telegram, издателя, Client ID, срок действия и привязку к попытке входа в этом браузере. Затем проверяет участие в сообществе и выдаёт обычную сессию приложения. Используется числовой Telegram ID, а не OIDC `sub` или username: повторный вход с того же аккаунта сохраняет карточку и права администратора. Запрашивается только публичный профиль; телефон и разрешение на личные сообщения не запрашиваются.

Сессия сохраняется в пределах вкладки, включая перезагрузку страницы. Ссылки `/?game=<ID>` продолжают работать после входа. При API-запросах участие в сообществе повторно проверяется с интервалом `FCZHK_MEMBERSHIP_CACHE_SECONDS` (по умолчанию 5 минут). Исторический профиль по одному совпадению имени автоматически не привязывается: игрок отправляет заявку из профиля, администратор подтверждает её в настройках. Выход из аккаунта отзывает текущую серверную сессию; просроченные сессии регулярно удаляет worker. Действующая сессия проверяется до повторного входа по initData.

Сайт должен иметь доступ к `telegram.org` для загрузки библиотеки входа, а сервер — к `oauth.telegram.org` для получения ключей. Не задавать `Cross-Origin-Opener-Policy: same-origin`: он блокирует взаимодействие с окном Telegram; допустим `same-origin-allow-popups`. Браузерные тесты используют имитацию Telegram; реальный вход проверяется после настройки BotFather и HTTPS.

## Выпуск и обновление

Production использует Linux, Docker Compose и Caddy. Подготовить `.env`, Telegram, DNS/HTTPS и PostgreSQL по [инструкции эксплуатации](docs/DEPLOYMENT_PLAN.md). База внутри Compose доступна на `db:5432`; её пароль должен совпадать с URL-encoded паролем в `FCZHK_DATABASE_URL`.

Если 443 занят другим сервисом, доступен [вариант HTTPS на 8443](docs/DEPLOYMENT_PLAN.md#если-порт-443-занят-другим-сервисом): отдельный Compose override, HTTP-01 на 80 и публичный адрес с `:8443`. Подготовка этих файлов не требует перезапуска Docker или существующих контейнеров.

```sh
bash scripts/deploy.sh ghcr.io/OWNER/REPOSITORY:FULL_40_CHARACTER_GIT_SHA
bash scripts/compose.sh exec app fczhk configure-bot
bash scripts/compose.sh run --rm tools fczhk check-bot
```

Использовать SHA успешного CI или digest образа. Deploy останавливает писателей, создаёт и полностью проверяет backup существующей БД, выполняет миграции, запускает сервисы и проверяет readiness. Успешный digest сохраняется в `.local/release-image`; обновление имеет окно недоступности. Текущая миграция — `a71f4b6d2e90`: назначения и отзывы прав администратора. Предыдущая `9c2d8f4a10b7` добавила уникальность имён игроков и автоголы с неизвестным автором. Повторяющиеся имена нужно разобрать до миграции; она не удаляет карточки автоматически. Downgrade новой миграции запрещён при сохранённых решениях владельца, чтобы не потерять права и отзывы.

CI публикует образ после проверок; сервер автоматически не обновляется. Реальный Telegram-пилот, offsite-хранилище и получатель тревог настраиваются отдельно. Откат к прежнему коду возможен скриптом только при неизменившейся ревизии схемы; восстановление БД выполняется по runbook в новую базу.

Для запуска без Docker после настройки окружения: `uv run fczhk migrate`, затем отдельными процессами `uv run fczhk serve` и `uv run fczhk worker`; polling требует ещё `uv run fczhk bot`. Webhook и polling одновременно не запускать.

```sh
uv run ruff check src tests migrations scripts

```

Полный контроль включает PostgreSQL, Playwright, ShellCheck, сборку контейнера и restore. Команды, изоляция данных и датированные результаты — в [документе тестирования](docs/TESTING.md). До слияния 17.10.2026 прошли 165 Python-тестов и 18 браузерных сценариев; CI merge-коммита также успешен.

## Границы текущей версии

Онлайн-оплаты, автоматические возвраты, личные уведомления и отдельные посты результатов не реализованы. Отменённая игра сохраняется в архиве; повторного открытия нет. Слияние конфликтующих карточек одной игры требует предварительного исправления данных.

[OpenSkill](docs/PLAYER_RATING_OPTIONS.md) остаётся экспериментом: на исходных 17 матчах преимущества перед ориентиром 50/50 не показано. Основной автоподбор использует оценки сообщества; допуски требуют проверки организатором на реальных составах. Минимальный дисбаланс вычисляется точно, выбор разнообразных вариантов — эвристически.

Приложение рассчитано на одно сообщество и один сервер. Лимитер входа и кэш рейтинга локальны процессу; рост истории и несколько API требуют новых замеров и общей инфраструктуры. Цели RPO 24 часа и RTO 60 минут подтверждаются только после настройки внешних копий и измеренного восстановления.
