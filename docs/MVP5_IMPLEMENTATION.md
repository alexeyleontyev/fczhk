## Пользовательские правила

Любой зарегистрированный игрок сообщества может прогнозировать счёт белых и чёрных, даже если он не участвует в этом матче. Для одного пользователя и игры хранится один текущий прогноз. Ввод открывается после утверждения команд, создание и изменение доступны строго до времени начала игры. В момент начала и позже запись запрещена сервером, в том числе по прямому API-запросу и из старой вкладки. Администратор не редактирует прогнозы других людей.

Начисление после завершения матча:

| Прогноз | Результат | Очки |
|---|---|---|
| 3:1 | 2:0 | 3: верные победитель и разница +2 |
| 4:1 | 2:0 | 1: верный победитель, другая разница |
| 0:0 | 2:2 | 1: верная ничья |
| 1:3 | 2:0 | 0: неверный исход |

Точный победный счёт даёт 3 очка; точная ничья — 1. Начисления не складываются. Общий зачёт суммирует очки всех прогнозистов по всем завершённым играм без ограничения периода или числа матчей. При равных очках место общее (1, 1, 3); имена/ID задают только стабильный порядок строк. Видны число прогнозов, число учтённых матчей и количество попаданий на 3 и на 1 очко. Черновики результата не оцениваются; исправление завершённого результата пересчитывает зачёт без повторного начисления.

## Принятые решения для пограничных случаев

- Чужие прогнозы раскрываются после начала матча; до этого доступны свой прогноз и общее число участников. Административная история не раскрывает скрытый счёт.
- Смена составов сохраняет прежний прогноз за белыми/чёрными. Пока команды не утверждены заново, изменения прогноза недоступны. После нового утверждения игрок видит предупреждение и может подтвердить/изменить прогноз до старта. Запрос из вкладки с прежней версией утверждения получает конфликт, а не молча принимается.
- Перенос времени возможен до прежнего начала. После наступления прежнего времени старта изменение времени запрещено, чтобы приём прогнозов не открывался повторно. При существующих прогнозах новое время должно быть в будущем: принятые прогнозы нельзя сделать запоздалыми задним числом. Место/стоимость/описание остаются редактируемыми.
- Счёт — неотрицательные целые числа до 200 на команду. Дробные, отрицательные, логические и строковые значения API отклоняет.
- Одновременные изменения одного прогноза проверяют ревизию; устаревшее изменение получает 409. Изменение прогноза не меняет административную версию матча.

## Реализация

Миграция `f5a039dc24be` добавляет `predictions`: составной первичный ключ матч/игрок, два счёта, ревизия, версия утверждённых команд, время сохранения. Рабочие транзакции PostgreSQL сериализуются блокировкой матча. Сервер проверяет время после ожидания блокировки и записывает это время приёма. Само наличие открытой формы не даёт права сохранить поздний прогноз.

Зачёт формируется одним SQL-чтением прогнозов и агрегированных голов завершённых результатов. Очки вычисляются по актуальным данным, не хранятся как накапливаемый счётчик. Это исключает двойное начисление при повторном завершении и автоматически учитывает исправления результатов, включая автоголы и голы без автора.

API: `GET /api/matches/{id}/predictions`, `PUT /api/matches/{id}/prediction`, `GET /api/predictions/standings`. Автор прогноза определяется из авторизованной сессии. В интерфейсе есть форма на карточке матча, отсчёт до старта по серверному времени, раскрытые прогнозы после старта и вкладка «Прогнозы» с общим зачётом.

Обновление с MVP 2/3/4: резервная копия, остановка старых процессов, `uv sync --locked`, `npm --prefix frontend ci`, `npm --prefix frontend run build`, `uv run fczhk migrate`, запуск сервисов. Backend проверяет правила начисления обоих победителей и ничьей, участие прогнозиста вне состава, создание/изменение, точный дедлайн, смену составов, перенос времени, приватность, ревизии, общий зачёт нескольких игр, общие места и исправления результата. PostgreSQL дополнительно проверяет одновременные изменения и истечение дедлайна во время ожидания блокировки матча.

Браузерные проверки теперь запускают собственный временный сервер на `127.0.0.1:8001` с отдельной временной БД и автоматическим завершением. Они не изменяют `.local/demo.db`. Сценарий MVP 5 проходит реальное наступление времени начала, отказ позднему запросу, получение 3 очков за разницу и пересчёт после ничьей. Проверяется ширина 390 и 320 px.

Проверено 20.09.2026: 101 backend-тест, 10 PostgreSQL-тестов и 9 браузерных сценариев MVP 1–5 прошли. Ruff и TypeScript/Vite проходят. Скриншоты прогноза и зачёта проверены визуально; отсутствие горизонтального переполнения проверено на 390 и 320 px.

## Отмена игры

Отмена будущего матча немедленно закрывает приём прогнозов; сохранённые прогнозы не удаляются. Отменённые матчи не участвуют в зачёте. Повторного открытия отменённой игры нет. Результат нельзя начать до фактического времени старта; черновик результата и отменённая игра не начисляют очков.
