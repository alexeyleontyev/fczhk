# Исторические результаты из Google Sheets

Актуализировано 17.10.2026. Это журнал конкретного импорта и инструкция его повторения. Указанные XLSX, SQLite и резервные копии локальны и не входят в Git; свежий checkout не содержит эти 17 игр. [Оглавление](README.md) · [Импорт в обслуживаемую среду](DEPLOYMENT_PLAN.md#импорт-истории-и-оценок).

Источник: [таблица «Игры 2026 upd»](https://docs.google.com/spreadsheets/d/1A9zju1qrvvLqfUXAx1E3hYplLoQ6iLNYLa-vMNOq58A/edit?gid=1942329478#gid=1942329478). Экспорт XLSX от 26.09.2026 сохранён локально в `.local/history-source-2026-09-26.xlsx` (SHA-256 `a65b073b145bc2b9b9901c462f17d7af5b78885baf2a58e7011b5293b3a12600`). Google-таблица не изменялась.

## Импорт в demo.db

26.09.2026 все 17 датированных вкладок (05.06–25.09.2026) импортированы в `.local/demo.db`. Прежние демонстрационные игроки и игры удалены. В базе 63 карточки, включая заглушки для неустановленных составов вратарей, 17 завершённых матчей, 293 участия и 196 событий голов. До первой замены сделана резервная копия исходного демо `.local/backups/demo-before-history-20260926T192055.sqlite3`.

Импортёр — [scripts/import_history.py](../scripts/import_history.py), подтверждённые поправки — [data/historical_import_corrections.json](../data/historical_import_corrections.json). Повторный запуск с `--replace-demo` снова заменит содержимое demo.db после резервной копии; без него пересекающиеся даты приводят к ошибке до записи. Для dry run:

```sh
uv run python scripts/import_history.py --xlsx .local/history-source-2026-09-26.xlsx
```

Импорт сохраняет итоговый счёт, фактические составы, голы, автоголы и передачи в `matches`, `match_results`, `result_participants`, `result_goals`. В `audit` для каждой игры лежат ID исходной таблицы, дата вкладки, SHA-256 XLSX, исходные ячейки A:G строк 1–51, текстовые примечания, исходные записи вратарей и строк голов. Оценки `DEF`/`AT` из старой таблицы сохранены только в исходных ячейках журнала; оценки сообщества [импортированы из другой таблицы](COMMUNITY_RATINGS_IMPORT.md).

Время начала и место исторических игр неизвестны. Для сортировки используется техническое время 12:00 МСК и техническое поле `location`; интерфейс показывает «Время и место неизвестны». Заявки, оплаты и публикации не выдумывались. Для входа в локальное демо роли администратора и игрока привязываются к двум импортированным полевым игрокам через условные Telegram ID 1001/1002. Эти связи нужны только локальному демо и не должны переноситься в PostgreSQL.

## Принятые исключения

| Дата | Обработка |
| --- | --- |
| 05.06 | «Рус не придет» оставлен в составе белых. Спорная передача чёрным в G28 сохранена только в журнале, без начисления. |
| 26.06 | В строках A10 и E10 описаны смены в воротах. По решению пользователя обе стороны представлены отдельными заглушками; исходные тексты сохранены. |
| 03.07 | Для белых A10 со сменой вратаря поставлена заглушка. Остальные голы до итогового счёта 6:11 записаны без авторов. |
| 10.07 | Недостающие до итогового счёта 3:7 голы записаны без авторов. |
| 07.08 | У чёрных E4 читается как «Джикия», E9 остаётся «Кузьма». |
| 28.08 | Передача «Валера» в G17 при автоголе Илюхи сохранена только в журнале, без начисления. |
| 11.09 | Для чёрных E10 вместо двойной записи «Толян / Серега» поставлена заглушка, поскольку полевые игроки сменялись в воротах. |

Пользователь подтвердил, что «Вратарь от Руса» 19.06 и 03.07 — один человек; обе игры связаны с одной карточкой, это не заглушка. Заглушки для других спорных вратарских составов перечислены в файле поправок. Их нельзя использовать как обычные персональные рейтинги до уточнения личности. Остальные имена из источника не объединялись по похожести. [Пример разбора последней игры](examples/historical-import-2026-09-25.json) сохранён для ручной проверки.

## Импорт в PostgreSQL

Скрипт принимает базу из `FCZHK_DATABASE_URL` и не зависит от SQLite, включён в Docker-образ вместе с картой поправок. Импорт исходной истории в реальную production-БД ещё не выполнялся. Для чистой базы после миграций команда имеет вид:

```sh
FCZHK_DATABASE_URL=postgresql+psycopg://... uv run python scripts/import_history.py --xlsx .local/history-source-2026-09-26.xlsx --apply
```

Перед записью в рабочую базу нужно отдельно сопоставить исходные написания с существующими карточками игроков: одинаковый псевдоним не доказывает, что это один человек. Текущий импортёр повторно использует существующую карточку с точно совпавшим псевдонимом и создаёт карточку для остальных; поэтому запуск на рабочей базе с игроками требует доработки явной карты соответствий и проверки коллизий. Флаг `--replace-demo` для PostgreSQL заблокирован.

## Связь истории с Telegram

В production импорт создаёт исторические гостевые карточки без условных demo ID. Игрок выбирает карточку в своём профиле, администратор проверяет соответствие и принимает заявку. Исходные участия и снимки сохраняются; расчёты разрешают связь с текущим профилем. Если обе карточки участвовали в одной игре, сначала исправить протокол — автоматического слияния конфликтующих участий нет.

При любом повторном импорте сначала сравнить SHA исходника, выполнить dry run и проверить фактический состав нескольких игр. Для непустой базы ограничение сопоставления по alias выше остаётся действующим; заявка на профиль не устраняет коллизии на этапе импорта.
