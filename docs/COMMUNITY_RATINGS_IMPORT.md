# Импорт оценок сообщества

Актуализировано 17.10.2026. Количества ниже относятся к выгрузке 26.09.2026; XLSX и demo.db не включены в Git. [Оглавление](README.md) · [Порядок production-импорта](DEPLOYMENT_PLAN.md#импорт-истории-и-оценок).

Источник: [таблица оценок](https://docs.google.com/spreadsheets/d/1C1Bl5yjC2oYNTqxnQ15cs-CP_EpGeDAo4vxldboPQX4/edit?gid=1423487120#gid=1423487120), вкладка `Оценки (8Х8)`. XLSX сохранён локально как `.local/community-ratings-source-2026-09-26.xlsx`; SHA-256: `b9aa4fa2dad6ef317a082d1b369c3ed177456d6f964006df16984ed7a10c35a7`. Исходная Google-таблица не изменялась.

26.09.2026 в локальную demo.db импортированы **589** заполненных пар `DEF`/`AT` от **14** оценщиков для **56** игроков. Пустые ячейки пропущены, нули сохранены как оценки. Восемь колонок без имени оценщика и вкладки `Прогресс оценок`/`Шизоприкидка` не использованы. Столбцы `C:E` — рассчитанные в таблице показатели, а не отдельные голоса; приложение считает обычное среднее по исходным оценкам авторов, поэтому его средние могут отличаться от `C:E`. Таблица не разделяет оценки полевых и вратарей: все 589 голосов отнесены к полевому амплуа, рейтинг защиты вратарей остаётся пустым до отдельных оценок.

По подтверждению пользователя имена оценщиков `Арт`, `Ястреб`, `Серёга Кип` сопоставлены с карточками `Артур`, `Виталик Ястреб`, `Серега`. Правила лежат в [community_rating_aliases.json](../data/community_rating_aliases.json). Добавлены семь оценённых игроков, которых не было после импорта матчей: Андрюша, Арсений Крам, Брат Крам, Братан, Герман Поридж, Мухаммад, Шаварш. Отдельных новых карточек оценщиков не потребовалось.

Оригинальные оценки хранятся в `imported_ratings` с точностью до 0,001, координатами исходных ячеек и SHA-256 файла. Это позволяет сохранить, например, `4,239` без округления до шага ввода в приложении. При новой оценке того же автора для того же игрока и амплуа учитывается новая оценка; импортированный голос остаётся в базе как источник. Объединение гостевой карточки с зарегистрированным игроком переносит её голоса при расчёте, не создавая повторного голоса. Администратор видит импортированные голоса с пометкой «из таблицы» в карточках зарегистрированных игроков; обычным участникам доступны средние оценки и общий зачёт.

В demo.db после импорта: **70** карточек игроков, **589** исходных голосов и прежние **17** завершённых матчей. Резервная копия до записи: `.local/backups/demo-before-community-ratings-20260926.sqlite3`.

Повторный импорт из того же файла не создаёт дубликатов. Если источник изменился, импортёр атомарно заменяет только записи этого источника. Проверка без записи:

```sh
uv run python scripts/import_community_ratings.py --xlsx .local/community-ratings-source-2026-09-26.xlsx
```

Для PostgreSQL после обычных миграций:

```sh
# FCZHK_DATABASE_URL заранее задан в .env для целевой базы.
uv run fczhk migrate
uv run python scripts/import_community_ratings.py --xlsx .local/community-ratings-source-2026-09-26.xlsx
# После проверки dry run:
uv run python scripts/import_community_ratings.py --xlsx .local/community-ratings-source-2026-09-26.xlsx --apply
```

Для повторного получения публичного XLSX: `https://docs.google.com/spreadsheets/d/1C1Bl5yjC2oYNTqxnQ15cs-CP_EpGeDAo4vxldboPQX4/export?format=xlsx`. После повторного скачивания сравните SHA-256 и выполните сухой прогон: таблица могла измениться.

Импортёр и карта alias включены в образ. Историю матчей импортировать первой, оценки — второй; перед записью в непустую БД проверить личности и совпадения имён. Новая выгрузка требует отдельного dry run и сверки, даже если имя файла прежнее. Реальный production-импорт не подтверждён локальными контрольными количествами.
