# Реализация MVP 1

Дата: 14 сентября 2026 года. Основа — раздел 18.2 ТЗ версии 1.5. Документ фиксирует реализационные настройки для еще не закрытых вопросов, не заменяя согласованные правила.

## Что реализовано

- Бот и Mini App; Telegram-подпись, срок авторизации, непрозрачные серверные сессии.
- Проверка членства в настроенном сообществе, администраторы по числовым ID.
- Профили/alias, гости и подтверждаемое администратором связывание с зарегистрированными пользователями.
- Черновики, шаблон и расписание, пост открытия, отдельные очереди и резерв.
- Отметки оплаты, финализация, административные включения, отказы, замены и подтверждаемый переход из резерва.
- Ручные белые/черные и вратари, проверка численности, утверждение и публикация.
- Версии, архив игр/составов, журнал административных действий и статус доставки.
- PostgreSQL-миграции, контейнеры, HTTPS-прокси, worker, скрипт резервного копирования.

## Настройки по умолчанию для открытых вопросов

| Вопрос | Реализованное поведение |
|---|---|
| Кто администратор | Список Telegram ID в `FCZHK_ADMIN_IDS`; пользователь не назначает себе роль |
| Разрешенное сообщество | Один `FCZHK_COMMUNITY_CHAT_ID`; публикации могут идти в другой `FCZHK_PUBLICATION_CHAT_ID` |
| Уход из сообщества | Доступ перепроверяется при входе и раз в 5 минут активной сессии; заявки автоматически не отменяются |
| Повторная запись после отказа | Новое время; оплату требуется подтвердить заново |
| Смена амплуа до финализации | Новое время; положительная отметка оплаты сохраняется |
| Административное включение до финализации | Место закрепляется, оставшаяся вместимость заполняется обычной очередью |
| Недобор | По умолчанию минимум 2 полевых; 0/1 вратарь допускается с явным отображением недобора; `REQUIRE_TWO_KEEPERS=true` делает двух вратарей обязательными |
| Нечетные составы | Разница полевых и общая разница участников не более 1; если вратарь один, назначить его с учетом общей численности |
| Пропущенное расписание | Открыть сбор после восстановления сервиса в той же неделе до начала пятничной игры; не создавать прошлые игры |
| Ручной черновик на дату пятницы | Расписание не открывает его автоматически; администратор открывает сам |
| Число открытых сборов | Возможно несколько на разные даты; в интерфейсе по умолчанию ближайшая предстоящая опубликованная игра |
| Отмена целой недели/повторное открытие | Не реализованы как неявные переходы; выключить расписание до наступления времени открытия |
| Связывание гостя | Администратор вручную подтверждает обе карточки; если у обеих есть заявка на один матч, операция запрещается без частичного слияния |
| Расписание по умолчанию | Выключено; включается после настройки реальных параметров |

Пределы 16 полевых и 2 вратаря соответствуют ТЗ и не редактируются в форме MVP 1. Отрицательная стоимость, время без часового пояса, неизвестное амплуа, выбор заявки другого матча и назначение одного игрока двум командам отклоняются сервером.

## Проверка и запуск в сообществе

Автоматические тесты покрывают основную очередь, отмены/повторную запись, смену амплуа, приоритет оплаты, финализацию, резерв, гостей, команды, сохранение истории, авторизацию и публикации. Отдельные PostgreSQL-проверки используют реальную миграцию и параллельные запросы. Браузерные сценарии проверяют мобильный административный процесс, видимость функций игрока и шаблон.

Результаты локальной проверки 14 сентября 2026:

- 20 тестов бизнес-правил, API, Telegram-обработчика и доставки — успешно.
- 2 дополнительных теста миграций и параллельных операций на PostgreSQL 17 — успешно.
- 3 браузерных сценария Chromium, включая мобильный путь от создания игры до публикации, — успешно; горизонтальной прокрутки на ширине 390 px нет.
- TypeScript и production-сборка Mini App — успешно.
- Docker-образ собран на Linux ARM64; uv lock учитывает Linux ARM64 и x86_64. Образ использует установленные зависимости без синхронизации при запуске.
- Из контейнера применены миграции на тестовую PostgreSQL. Демонстрационные данные сохранены через `pg_dump -Fc` и восстановлены через `pg_restore --exit-on-error` в отдельную БД: 21 профиль, 1 игра, 20 заявок.

Тестовая БД и браузерная демонстрация изолированы от реальных Telegram-данных. Резервное восстановление проверяет механизм, но не доступность будущего внешнего хранилища владельца.

До реального запуска нужны: токен бота, ID сообщества и места публикаций, ID администраторов, HTTPS-домен, настоящие место/время/стоимость/реквизиты. Эти значения не выдумываются и не сохраняются в Git.

После настройки необходимо выполнить реальный Telegram smoke test: вход участника и отказ постороннему, открытие сбора, запись двух человек в разных амплуа, отметка оплаты, ручное утверждение, отправка и пометка устаревшего поста. Проверить Mini App на iOS и Android. Этот внешний этап не заменяется локальной имитацией Telegram.

## Ограничения

- Статистика, рейтинги и аукцион отложены по плану MVP.
- Реальный бот не отправлял сообщения без предоставленных доступов.
- При неопределенном результате Telegram-доставки требуется сверка чата администратором.
- Полное восстановление проверено на тестовых данных; внешнее расписание и хранилище резервных копий настраиваются на инфраструктуре владельца. Оглавление дампа само по себе не доказывает успешное восстановление.
- Массовое слияние конфликтующих гостевых историй, управление администраторами из UI и отмена целой игры не входят в текущие согласованные обязательные сценарии MVP 1.
